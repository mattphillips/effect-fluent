## P0 — interop crashes (typechecks, dies at runtime)

- [x] **1. Fluent Exit/Effect implement core `Effect` without the evaluate
  protocol** — `Exit.ts:39`, `Effect.ts:34` (CONFIRMED)
  **Resolved by design decision**: direct core execution of fluent values is
  intentionally unsupported — the boundary is explicit unboxing via
  `.effect`/`.exit` (fluent run functions will cover the run story when they
  land). The misleading class JSDoc was fixed to document exactly that, and
  tests assert the unboxing path.

- [x] **2. `Effect.sleep` rejects/mangles the fluent Duration** —
  `Effect.ts:493` (CONFIRMED)
  Still typed with core `Duration.Input`; `Effect.sleep(Duration.seconds(5))`
  is a compile error, and untyped callers get the wrapper decoded as an empty
  DurationObject → `Duration.zero` → sleeps 0ms silently. Fix: accept the
  widened fluent `Duration.Input` and unwrap, like Schedule's constructors.

## P2 — type-safety tradeoffs to revisit

- [x] **5. Schedule `Input` typed `any` across repeat/retry surfaces** —
  `Effect.ts:1051` + retry (1115), repeatOrElse (1080), scheduleFrom (1176),
  `Repeat.Options.schedule` (1520), `Retry.Options.schedule` (1552) (CONFIRMED)
  Input-mismatched schedules compile and kill the fiber with a TypeError where
  core rejects at compile time. Revisit: overload pairs
  (`Schedule<_, A>` / `Schedule<_, unknown>`) instead of `any` — unions broke
  inference, but separate overloads should not.

- [x] **6. `repeatOrElse` unguarded `meta.output` cast** — `Effect.ts:1088`
  (PLAUSIBLE)
  Codifies upstream's private runtime shape (`Option<Metadata>`) against its
  public signature (`Option<B>`). If a future beta in the `^` peer range aligns
  runtime with the public type, orElse silently receives
  `Option.some(undefined)`. Fix: runtime shape check before projecting.

- [x] **7. `repeatOrElse` missing branch tests** — `repetition.test.ts:317`
  (CONFIRMED)
  Only the `Option.some` branch is tested; the `none` branch (failure before
  any schedule step) and the normal-completion branch are not. Fix: add both.
